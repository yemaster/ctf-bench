# Web — 打折商店的负数订单

- **方向**：Web
- **难度**：中等偏难
- **分值**：100
- **预计时间**：25–35 分钟
- **知识点**：前端信息泄露、Base64、业务逻辑漏洞、整数/负数校验缺失、隐藏 SKU

## 背景

培训部搭了一个只在本机运行的小商店，给学员的测试账户余额只有 50 美元。
商店里有一件不公开的 “Flag License”，只有员工促销码才能解锁。
采购流程看起来会检查余额，但实现它的实习生对“数量”有着自己的理解。

## 目标

从正在运行的服务中取得形如 `flag{...}` 的 flag。flag 只会在成功下单隐藏商品后由服务端返回。

## 学员材料

- `public/index.html`：商店首页
- `public/app.js`：前端逻辑（请仔细阅读注释和常量）

服务地址由讲师提供，例如 `http://127.0.0.1:8080`。

## 规则与边界

- 只允许访问讲师提供的本地 `127.0.0.1` 服务，不要扫描或攻击其他地址。
- 不允许拒绝服务、爆破口令或修改服务器文件。
- 允许使用浏览器、`curl`、Python 标准库等常规工具。
- 这不是真实商店，所有商品、余额和 flag 均为本地合成数据。

## 提示

1. 前端源码里可能留着不该上线的“种子”。
2. 解锁隐藏商品后，注意下单接口对 `qty` 的信任程度。
3. 总价、余额和数量之间，哪个比较运算可以被绕过？

## 交付

提交 flag 文本，并简要说明获取它的两个关键步骤。
